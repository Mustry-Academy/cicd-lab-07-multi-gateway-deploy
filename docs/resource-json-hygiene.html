How we keep Ignition's junk out of our resource files

Ignition stamps every resource manifest with metadata that has nothing to do with your project. We hide that junk from diffs, and we revert it automatically before it can enter a commit.

01The junk

Every resource folder has a resource.json next to it. Most of it is real config we want in git. Two fields are bookkeeping that Ignition rewrites on its own.

{
  "scope": "G",
  "version": 1,
  "restricted": false,
  "overridable": true,
  "files": ["view.json", "thumbnail.png"],
  "attributes": {
    "lastModificationSignature": "0b8bec8b...36369a",   <-- junk
    "lastModification": {                               <-- junk
      "actor": "admin",
      "timestamp": "2026-05-21T13:34:18Z"
    }
  }
}
Green: keepDescribes the resource itself. Only changes when a person changes something. This is what we want to see in a pull request.
Red: junkWho saved it and when, plus a hash. Ignition rewrites these every time it touches the resource, even when nothing about your project changed.
Scale

This repo tracks 417 resource.json files. 384 of them carry those junk fields. Open the Designer, save a few views, and you get a pile of modified files where nothing real changed.

02Two tools, and they are not the same thing

This is the part that trips people up. One tool makes the junk invisible. The other one removes it. They solve different halves of the problem and you need both.

Tool 1

Hide it

scripts/git-diff/normalize-ignition-resource-json.py
wired by .gitattributes + setup.sh

Before git prints a diff, it runs the file through a filter that deletes the two junk fields. Both sides come out identical, so git diff shows nothing.

  • Runs automatically, always
  • Pull requests stay readable
  • Does not touch the file on disk
  • The file stays modified, and git status still lists it
≠
Tool 2

Revert it

scripts/clean-ignition-resource-churn.sh
run by the pre-commit hook

Compares the file against the committed version with the junk fields stripped. If nothing real changed, it runs git restore and the file goes back to how it was.

  • Removes the junk from disk
  • Runs on every commit
  • Catches junk you already staged with git add .
  • Never touches files with real edits
The rule to remember

An empty git diff does not mean the file is clean. It means the junk is hidden. Tool 1 alone would leave that junk on disk, ready to be committed. Tool 2 is what actually keeps it out.

03What happens when you save a view

Follow one Designer save through to a commit.

Designer save to commit
You save a view in the Designer
Ignition rewrites that view's resource.json with a fresh timestamp and signature. Nothing real changed.
git status lists the file
The modification is real on disk, so git sees it.
git diff shows nothing
Tool 1. The junk is stripped from both sides before the diff renders.
You commit
Tool 2. The pre-commit hook runs the revert script. Junk-only files are restored and drop out of the commit. Files with real edits are left alone.
The commit contains only real changes.

04The moving parts

Four files, plus one command that wires them up.

.gitattributes

Marks every resource.json as diff=ignition-resource, which points git at the normalizer, and as linguist-generated, which collapses these files by default in pull requests.

scripts/git-diff/normalize-ignition-resource-json.py

Tool 1. Parses the JSON, drops the two junk fields, re-emits it sorted. Anything it cannot parse passes through untouched, so a broken file never breaks your diff.

scripts/clean-ignition-resource-churn.sh

Tool 2. Normalizes the working copy and the committed copy, compares them, and restores the file when only junk differs. Looks at both unstaged and staged changes.

scripts/git-hooks/pre-commit

Runs Tool 2 on every commit. Installed by setup.sh as a symlink into .git/hooks/.

One command wires all of it

scripts/setup.sh
#   → git config diff.ignition-resource.textconv ...   (Tool 1)
#   → .git/hooks/pre-commit → scripts/git-hooks/pre-commit  (Tool 2)

You can also run Tool 2 by hand at any time:

scripts/clean-ignition-resource-churn.sh              # show what is junk-only
scripts/clean-ignition-resource-churn.sh --apply      # revert it

05How the revert decides what is safe to throw away

It never guesses. It strips the junk fields from both the current file and the committed one, then compares what is left. Three outcomes.

Outcomes
Junk only, not staged
restored: the file drops out of git status entirely.
Junk only, already staged
restored (was staged): unstaged and reverted, so git add . cannot slip it into a commit.
A real edit is present
skip staged, has real changes: the file is left completely alone. Human edits always win.
Why the script uses --no-textconv internally

The script has to ask git whether a file is staged. That check must pass --no-textconv, otherwise git runs Tool 1 first, the junk fields are stripped, both sides compare equal, and git reports the file as not staged at all.

Tool 1 will happily hide the junk from the code written to catch it. Same rule as before, one level deeper: an empty diff never means an unchanged file.
